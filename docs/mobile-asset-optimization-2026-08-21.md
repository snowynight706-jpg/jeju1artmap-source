# 모바일 화면 자산 최적화 기록

## 적용 기준

- 승인 디자인, 캔버스 비율, 투명 경계, 앵커 여백과 지도 배치값을 바꾸지 않는다.
- 공개 모바일은 시작할 때 한 번 선택한 자산을 확대·축소 중 계속 사용한다.
- PC·관리자 화면은 기존 512px 화면본, 인쇄·내보내기는 기존 고해상도 원본을 유지한다.
- 128·256·512px 사이의 런타임 승격·강등과 추가 디코딩은 사용하지 않는다.

## 채용 자산

| 대상 | 화면 형식 | 판단 |
|---|---|---|
| 랜드마크 54종 | 384px WebP | 512px 화면본과 육안 차이가 거의 없고 256px에서 보인 간판·기와·외벽 선의 부드러움을 피함 |
| 카테고리 UI 5종 | 96px 무손실 WebP | 기존 PNG와 픽셀 RMSE 0, 투명도·여백 동일 |
| 재단 로딩 CI·헤더 심벌 | 공식 원본 SVG | 공식 AI의 곡선 경로를 사용하고 기존 화면 색상·비율을 유지 |
| 범용 마커 | 기존 SVG | 이미 작고 확대 선명도가 높아 래스터 변환 이점 없음 |
| 베이스맵 | 기존 화면용 WebP | 복잡한 마스터 SVG의 모바일 실시간 래스터 비용을 피함 |
| PWA 설치 아이콘 | 기존 PNG | manifest·홈 화면 아이콘 호환 유지 |

랜드마크 일러스트와 카테고리 일러스트는 자동 벡터화하지 않았다. 자동 추적 SVG는 질감·반투명 경계·선 모양이 달라질 수 있고 경로 수가 늘어 모바일 렌더 비용이 오를 수 있다. 재단 CI는 초기 무손실 WebP 적용 후 재단 공식 AI 배포 원본을 확보해 순수 path SVG로 교체했으며, 자동 추적은 사용하지 않았다. 세부 선별과 무결성 값은 `svg-asset-selection-2026-08-21.md`에 기록한다.

## 측정 결과

| 비교 대상 | 전송 합계 | RGBA 디코딩 메모리 추정 |
|---|---:|---:|
| 현재 활성 랜드마크 14종·512px | 1,202,744B | 14,331,904B |
| 모바일 활성 랜드마크 14종·384px | 190,686B | 8,062,464B |
| 전체 랜드마크 54종·512px | 1,832,222B | 53,907,456B |
| 전체 랜드마크 54종·384px | 632,896B | 30,325,248B |

- 현재 활성 14종 기준 전송량 약 84% 감소, 디코딩 메모리 약 44% 감소다.
- 카테고리 UI 5종은 55,763B에서 40,274B로 감소했다.
- 재단 CI 2종은 중간 단계의 WebP 합계 48,760B에서 gzip 기준 SVG 합계 13,007B로 추가 감소했다.

## 시각 검수

- 512·384·256px를 같은 화면 크기로 비교했다.
- 384px은 칠성로 간판, 목관아·관덕정 기와, 소통협력센터 외벽, 아트플랫폼 창호가 현재 화면본과 거의 같게 보였다.
- 256px은 같은 세부 요소에서 선명도 저하가 확인돼 적용 대상에서 제외했다.
- 384px 파생본의 가로세로 비율과 알파 경계 상자는 512px 화면본과 같은 비율로 유지된다.

실제 저사양 기기의 시작 시간과 드래그·확대 정착 개선 폭은 배포 후 신규 성능 진단 기록으로 확인한다.
